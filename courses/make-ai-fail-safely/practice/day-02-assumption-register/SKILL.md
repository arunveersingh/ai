# Assumption register

**Silent assumption inheritance** is when the model fills gaps with likely defaults and builds on them as if you decided them. Fix it in two moves: **ask** so missing premises surface as ASSUMED/UNKNOWN (and details as GIVEN/FILLED-IN), then **verify** each fill-in before you treat the plan as yours.

Paste Part A into any chat. Do Part B yourself. Swap brackets. Tighten or drop rules if you need to.

## Part A — Ask (paste / adapt)

```
Task: [YOUR INCOMPLETE BRIEF]

Rules:
1. First, list every premise you need that I did not state. Label each ASSUMED or UNKNOWN.
2. Label every concrete detail in your answer GIVEN (from my words) or FILLED-IN (not from my words).
3. Do not invent flag names, channel names, owners, dates, percentages, environments, or team rituals. If missing, write UNKNOWN.
4. Do not treat ASSUMED or FILLED-IN items as decided. Build the plan only on GIVEN items plus UNKNOWN placeholders I must fill.
5. If you cannot proceed without a missing constraint, stop and list the UNKNOWNs — do not quietly pick a default.
```

**Optional tighteners:** ban extra classes you care about (SLAs, regions, data classes). Prefer "list assumptions first" over open "draft a full plan."

## Part B — Verify (you do this)

1. **Require the register.** No ASSUMED/UNKNOWN list → fail the draft and re-run Part A.
2. **Accept / replace / reject** each ASSUMED or FILLED-IN item. Do not mentally accept a default because it sounds normal.
3. **Draft vs decided.** Keep the reply as a **draft**. Promote a line only after it was GIVEN or you explicitly accepted a fill-in.
4. **Block on real UNKNOWNs.** Name which missing constraint would break the plan if left open. If none would, the UNKNOWNs were decoration — tighten Part A.

**Done when:** you have a marked register (accept/replace/reject) and at least one blocking UNKNOWN, or you correctly stopped until the brief is complete enough.
